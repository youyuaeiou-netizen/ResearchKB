LLM 知识库

最近我发现一件非常有用的事情：使用 LLM 来构建个人知识库，针对各种研究兴趣主题。这样，我最近的大部分 token 消耗不再主要用于代码操作，而是更多地用于知识操作（以 Markdown 和图像的形式存储）。最新的 LLM 在这方面表现得相当出色。所以：

数据摄取：

我将源文档（文章、论文、代码库、数据集、图像等）索引到一个 raw/ 目录中，然后使用 LLM 逐步“编译”一个 wiki，它只是一个目录结构中的 .md 文件集合。这个 wiki 包括 raw/ 中所有数据的摘要、反向链接，然后它将数据分类为概念，为它们撰写文章，并将它们全部链接起来。要将网页文章转换为 .md 文件，我喜欢使用 Obsidian Web Clipper 扩展，然后我还使用一个快捷键将所有相关图像下载到本地，以便我的 LLM 可以轻松引用它们。

IDE：

我使用 Obsidian 作为 IDE 的“前端”，在那里我可以查看原始数据、编译后的 wiki，以及派生的可视化。重要的是要注意，LLM 编写并维护 wiki 的所有数据，我很少直接触碰它。我试用过一些 Obsidian 插件，以其他方式渲染和查看数据（例如 Marp 用于幻灯片）。

问答：

有趣的地方在于，一旦你的 wiki 足够大（例如，我关于最近某些研究的 wiki 有 ~100 篇文章和 ~400K 字），你就可以向你的 LLM 代理提出各种复杂问题针对 wiki，它会去研究答案，等等。我原本以为需要使用花哨的 RAG，但 LLM 在自动维护索引文件和所有文档的简要摘要方面表现得相当好，而且在这个 ~小规模 上，它相当容易阅读所有重要的相关数据。

输出：

我喜欢让它为我渲染 Markdown 文件，或者幻灯片（Marp 格式），或者 matplotlib 图像，所有这些我随后又在 Obsidian 中查看。根据查询，你可以想象许多其他可视化输出格式。通常，我最终会将输出“归档”回 wiki 中，以增强它以供进一步查询。所以我自己的探索和查询总是在知识库中“累积”。

Linting：

我对 wiki 运行了一些 LLM “健康检查”，例如找到不一致的数据、推断缺失数据（使用网络搜索）、找到有趣的连接作为新文章候选等，以逐步清理 wiki 并提升其整体数据完整性。LLM 在建议进一步提出的问题和调查方面相当出色。

额外工具：

我发现自己正在开发额外的工具来处理数据，例如，我随意编写了一个小型而朴素的 wiki 搜索引擎，我既直接使用它（在 web UI 中），但更经常的是我想通过 CLI 将它交给 LLM 作为更大查询的工具。

进一步探索：

随着代码库的增长，自然的愿望是考虑合成数据生成 + 微调，让你的 LLM “知道”数据嵌入其权重中，而不是仅仅上下文窗口。

TLDR：来自给定数量来源的原始数据被收集，然后由 LLM 编译成一个 .md wiki，然后由 LLM 使用各种 CLI 操作来进行问答并逐步增强 wiki，所有这些都可以在 Obsidian 中查看。你很少手动编写或编辑 wiki，它是 LLM 的领域。我认为这里有空间开发一个令人惊叹的新产品，而不是一堆 hacky 的脚本集合。
