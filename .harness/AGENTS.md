# ResearchKB 工作区全局参考规则

适用范围：本仓库的 `.harness` 及其子目录（当前检出位置：`F:\ResearchKB\.harness`）。本文件承接
本机工作台的通用协作规则；仓库根目录的 `AGENTS.md` 提供更宽范围的 ResearchKB 项目约束。

## 优先级与基本行为

- 系统、开发者和安全要求优先；其后遵循用户当前明确请求、适用的本地规则和历史记录。
- 默认使用中文，直接、简洁、准确地沟通。
- 行动或回答前先检查实际文件和当前状态；不得以记忆、旧报告或猜测替代可执行的核验。
- 明确标注假设、不确定性、跳过的检查、失败和未验证结果；不得编造事实、引用、数据、文件内容或能力。
- 回答、解释、审阅、诊断、检查、总结、建议和计划默认只读；只有明确要求实现、修改、修复或配置时才写入文件。

## 范围、安全与修改

- 只做任务所需的最小改动，保留无关文件、人工内容、原始数据、实验观察、页码、说明和项目约定。
- 删除、覆盖、批量重命名、迁移目录、改配置、数据库或原始数据操作、外部写入、发布、凭据及安全敏感变更，先说明影响并取得明确授权。
- 高风险改动先检查目标；尽可能采用 dry-run、精确 diff、可回滚方案和修改后核验。
- 不暴露、复制、记录或提交密钥、令牌及其他秘密。只清理本次产生的临时且不可复用文件；保留可复用脚本和模板。

## 工具、上下文与验证

- 使用最小且相关的工具、插件和技能；优先复用现有脚本、模板和工作流。
- 先缩小范围，再读取相关文件；文本搜索优先使用 `rg`，避免无目的递归扫描和重复读取。
- 机械性任务优先使用确定性本地工具；验证只覆盖改动及其主要风险，不运行无关的完整测试。
- 修改后按需检查 diff、编码、语法、链接、图片、公式、脚本、测试及内容是否遗漏、重复、错位或越界。
- 只有有证据时才声明成功；最终报告已完成的工作、变更文件、验证结果、警告、未解决风险和必要的下一步。

## 连续任务与交接

- 用户明确要求持续、逐批或直到条件满足时，逐项核验终止条件；未满足前继续，除非用户停止或确实被阻塞。
- 从状态文件、日志或游标恢复，不重复已完成工作；记录单项失败并继续处理其他可行项。
- 用户说“更新交接文档”时，先读取工作台交接索引和指定项目交接文档，核对实际状态后原位更新唯一正式交接文档；不新建 dated、v2、final、backup 或并行版本，并在写后校验路径、计数、状态和范围一致性。

## Windows PowerShell 7

- 执行 PowerShell 命令或脚本时必须显式调用：
  `C:\Program Files\PowerShell\7\pwsh.exe -NoLogo -NoProfile`。
- 除非明确验证 Windows PowerShell 5.1 兼容性，不调用 `powershell.exe`，也不降低 ExecutionPolicy 或关闭安全功能。
- 验证 PowerShell 结果时，在同一子进程输出 `$PSVersionTable.PSVersion` 和 `(Get-Process -Id $PID).Path`。

## ResearchKB 自动化执行层

- Codex 工作区根目录是仓库根（当前为 `F:\ResearchKB`）；`.harness` 仅是其内部执行层。任务可从任意目录启动，但必须将子进程 cwd 设为该工作区根。
- 脚本从自身位置推导 `.harness` 与工作区根路径，禁止将调用时 cwd 当作路径依据。配置中的相对 `workspace_root` 与 `harness_root` 均相对于工作区根解析。
- `config`、`scripts`、`tasks`、`staging`、`runs`、`reports`、`logs`、`state`、`cache`、`inbox`、`tests` 与 `vendor` 均属于执行层；所有临时和运行性产物只能写入这些 `.harness` 子目录。
- 正式 Vault 写入仅限用户明确授权的受控操作；默认 dry-run。自动更新只修改 `CODEX MANAGED` 区域，并且不得覆盖、移动或删除既有内容，不得修改 Zotero、`.obsidian` 或 `_system`。
- v3 的 `daily`、`weekly`、`query` 与 `lint` 从工作区根调用 `.harness\scripts\researchkb_v3.py`。Codex CLI 的 cwd 为工作区根，但生成输出只可写入 `.harness\staging`。
- 每次 `--apply` 前完成路径、来源去重与受保护区域校验；记录 run id、范围、来源与内容 SHA-256、证据锚点以及受保护区域前后哈希。
- X、知网和 ScienceDirect 不使用绕过登录、反爬或版权限制的无人值守抓取。来源失败写入报告，其他来源继续处理；旧维护任务不得与 v3 同时正式写入候选。
