# ResearchKB 研究身份与需求（v3 草案）

## 身份与工作方式

- 我是材料科学研究者，维护本地优先、证据可追溯的 ResearchKB。
- Zotero 是书目、PDF 与引用的权威来源；Obsidian 用于浏览、审阅与人工确认；Codex 在 `.harness` 中执行采集、去重、候选编译、查询、Lint 与报告。
- 自动化只能产生可审核候选，不能替代实验判断、证据核验或正式知识晋级。

## 当前学习与研究优先级

1. 当前 90 天学习主线：相图 → 凝固 → 相变；输出为带来源的概念卡与跨主题关系图。
2. 材料基础：固体结构、晶体缺陷、扩散、相图、凝固和相变。
3. 后续研究方向：金属增材制造，尤其是激光粉末床熔融（LPBF），以及工艺—缺陷—显微组织—性能关系。
4. 材料机器学习：仅在数据、特征、验证条件和可解释性明确时纳入候选。

## 知识准入与输出要求

- 优先：Zotero 文献、DOI/公开元数据、官方期刊 RSS、受审阅的 GitHub 项目、用户主动导入的本地资料。
- 每项候选都要保留来源 URL/DOI/路径、证据位置、内容哈希、采集时间与运行编号。
- 明确区分原始证据、候选、自动可用知识和人工核验知识。自动化可将来源完整的内容写入 `02-Areas/_Codex-Auto` 并标记为 `auto-reusable`，但不得自动标记 `verified`，也不得覆盖人工 Areas、Projects 或 Skills。
- 对声称实验性能、工艺窗口、机理或模型效果的内容，必须标记缺失条件，不能补造数值或因果结论。

## 信号过滤偏好

- 优先高信息密度的论文、数据集、开源材料计算/表征/工艺工具、软件发布和可复现实验资源。
- 降低与研究无关的泛 AI 新闻、消费电子、融资宣传、无证据观点和重复转载的优先级。
- GitHub 只跟踪用户确认的公开账号活动和公开仓库 release。Horizon 的四类动态均进入候选处理：能映射到当前学习主线的内容进入概念卡，其他内容保留为“扩展探索”，不作为基础事实。X 仅使用经审核账号的固定 search、禁用 replies 与回复扩展；不使用 Playwright、登录绕过或反爬规避。Horizon 的频率、账号池、预算和部分覆盖规则只以 `horizon-fetch-only.json` 为准，避免在本文件重复维护会漂移的运行参数。
