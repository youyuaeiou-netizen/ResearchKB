## CPU 电压：必须保持诚实

- Ryzen 9700X 下，LibreHardwareMonitor 可列出每核 `Core #n VID`，但它们只是核心请求电压，不是实际 Vcore；禁止作为 CPU 电压摘要。
- ITE 的匿名 `Voltage #1` 已恢复为“主板电压 #1”，不得再映射为“CPU 核心电压”。此前显示的约 1.4–1.5 V 已证实不是可验证的 CPU Vcore。

- “CPU封装功耗”与“CPU总占用”目前来自 LibreHardwareMonitor，分别表示 Package 功耗和全 CPU 总负载；它们与 GamePP 的刷新时刻/统计窗口可不同，不能通过伪造或校正系数强行对齐。

## 其他功能与边界

- 主页网络卡只显示连接、出口 IP、下载、上传；出口配置仅存在已忽略的 `.env.local`。
- 天气使用浏览器定位与同源 Open-Meteo 接口；Ollama 不可用时显示离线，不伪造模型。
- 本地 Qwen 不消耗 Codex 云端额度；Ollama 服务可静默常驻，但模型仍按生命周期策略占用显存。OpenCode、ObsUI 和自动化若同时修改同一工作区文件或同时调用 Ollama，仍会出现文件竞态或请求排队；阅读器自动释放对外部消费者采用活动连接保护，实际并发仍需验收。后台文献任务建议使用 64K，200K 仅手动使用。
- 截图辅助进程只处理桌面像素、选区、剪贴板和 PNG 保存；网页端不接触任意桌面路径，也不记录截图内容。截图标注工具、OCR、整篇自动翻译、翻译导出仍不在首版范围。
- H.D.D 的 Codex 提供方继续使用 `--sandbox read-only`；本地 Ollama 只访问 loopback。外部 CLI 虽以参数数组/stdin 调用并拒绝 shell 元字符，但可能继承该工具自己的文件与网络权限，不能宣称全局只读。
- 文献扫描和分析可自动执行，但所有 Zotero 写入都必须由用户点击“确认入库”；作者等书目信息优先通过 PDF/DOI/Crossref 自动补齐，仅在无法可靠识别时人工复核。低置信度、组合重复匹配和模型失败仍必须支持人工修正。所有 Zotero 写入串行、按 DOI/哈希/标题组合去重并写后回读，不允许模型直接执行任意 PowerShell、修改 Zotero 内部数据库或删除原始 PDF。
- 启动加载层已完成此前视觉验收，但当前深色界面仍不能称为绝区零官方高保真复刻。
- 不实现历史温度曲线或持久化，除非用户明确确定保留周期、存储位置和隐私范围。
