## 实时性能监测

接口：`GET /api/system-metrics`（由 `vite.config.ts` 的 Vite 插件提供）。

| 显示项 | 本地来源 | 含义 |
| --- | --- | --- |
| CPU | `Win32_PerfFormattedData_PerfOS_Processor` 的 `_Total` | 总 CPU 使用率 |
| GPU | `Win32_PerfFormattedData_GPUPerformanceCounters_GPUEngine` | 所有 GPU 引擎中的最高使用率 |
| MEM | `Win32_OperatingSystem` | 已用物理内存占比 |
| DISK | `Win32_PerfFormattedData_PerfDisk_PhysicalDisk` 的 `_Total` | 物理磁盘活动时间占比，不是容量占用 |

实现限制：

- 仅在 `pnpm dev` 或 `pnpm preview` 的 Vite 进程中提供该接口；单独托管 `dist` 静态文件不会有实时指标。
- GPU 当前显示最繁忙引擎的峰值，DISK 当前显示全部物理磁盘汇总；尚未提供设备选择器。
- Windows 性能计数器不可用时，前端保留不可用状态，不回退为固定或伪造读数。

## 网络监测与代理客户端

接口：`GET /api/network-metrics`、`POST /api/flclash/launch`、`GET /api/network-egress`、`POST /api/network-egress/refresh`、`GET /api/local-models`。

- `GET /api/network-metrics` 每 2 秒读取当前 IPv4 默认路由对应的 Windows 网卡；速率由累计收发字节相邻样本计算，首个样本或适配器变化时显示 `—`。
- 服务端每 5 秒异步测一次 `1.1.1.1:443` TCP 握手。它反映基础上网路径，不等于代理节点延迟；仅 TUN 路由场景可能经过代理。
- `POST /api/flclash/launch` 不接受任何浏览器传入的路径。仅当 `.env.local` 中的 `OBSUI_FLCLASH_PATH` 指向存在的 `FlClash.exe` 时才会启动；运行中的 FlClash 会尝试恢复前台窗口。
- `POST /api/clash-verge/launch` 不接受任何浏览器传入的路径。仅当 `.env.local` 中的 `OBSUI_CLASH_VERGE_PATH` 指向存在的 `clash-verge.exe` 时才会启动；运行中的 Clash Verge 会尝试恢复前台窗口。
- 出口 IP 查询默认关闭。只有 `.env.local` 同时提供 loopback `OBSUI_FLCLASH_PROXY_URL` 与 `OBSUI_IPINFO_TOKEN`，应用才会经该代理请求 IPinfo Lite；配置有效时每 60 秒自动更新，用户仍可在“状态监控”页手动立即刷新。
- 首次打开页面时，右侧卡会自动尝试更新出口 IP；成功结果会同步显示在右侧卡，包含出口 IP、国家/地区和 ASN；该结果只保存在当前 Vite 进程内存。
- 本地模型卡片每 30 秒读取一次本机 Ollama 的 `/api/tags`，只显示已安装模型的数量与名称；Ollama 不可用时显示离线状态，不改变 H.D.D/Codex 的对话链路。
- 用户已于 2026-08-21 在本机完成一次手动出口 IP 刷新验证。不得在本文档、截图、日志或 Git 中记录 IPinfo token、订阅链接、实际出口 IP 或其他凭据。
- 查询只保留出口 IP、国家/地区码、ASN 和组织名于 Vite 进程内存；不写入 IndexedDB、日志、备份或 Git，且缺少配置/代理异常时不会直连回退。
- 本版不启用或扫描 Mihomo Controller，不显示/修改节点、协议、节点延迟或代理流量。
- VPN 套餐剩余流量未实现。FlClash 代理端口和出口 IP 查询不能可靠推出服务商套餐余量；后续只能在用户明确授权并提供本机配置来源后，接入服务商 API 或订阅响应中的 `subscription-userinfo`，且仍不得把订阅 URL 或 token 写入仓库。
